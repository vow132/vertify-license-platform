# 安全基线

## 密钥管理

- 服务端 Ed25519 签名私钥、X25519 KEX 私钥、卡密 HMAC 主密钥：生产一律存 KMS/HSM/Vault，
  通过 `crypto.Signer` 接口注入；仓库/镜像/数据库/客户端中不存在任何真实私钥。
- 信封加密 KEX 密钥分版本（kid）轮换：新增 kid → 观察客户端 bootstrap 覆盖率 → 停用旧 kid。
- 签名密钥轮换：`sign_keys` 多 kid 并存 → 新 kid 设为 active → 观察客户端兼容率 → 移除旧 kid。
- 卡密 HMAC 主密钥轮换需要双检索窗口（新旧 HMAC 并行查询）+ 全量卡密重哈希迁移，见运维手册。
- 本地开发密钥由 `cmd/keygen` 生成，仅限开发环境。

## 数据保护

- 卡密：数据库仅存 `HMAC-SHA256` 检索值 + 展示前缀；明文仅在制卡响应/导出中出现一次并审计。
- 口令：Argon2id（m=19MiB, t=2, p=1，OWASP 底线；可上调）。
- 会话：cookie 存 256-bit 随机 token，库存 SHA-256；HttpOnly + Secure + SameSite=Strict。
- 硬件指纹：仅分量 SHA-256 摘要；服务端盐合并后入库。
- 日志：结构化访问日志不含 body；敏感字段（卡密/令牌/设备标识）禁止入日志。

## 传输

- 客户端面与管理面强制 TLS 1.3+（生产建议网关终结并启用 HSTS、OCSP stapling）。
- 应用层信封加密覆盖激活/兑换载荷（TLS 终止点也不可见明文卡密）。
- 管理面与公开面独立端口/域名/网关策略。

## 应用层对抗

- 防重放：nonce 原子消费（SETNX + TTL）+ 设备序列号严格递增（Redis 先行、DB 兜底）。
- 限流：IP 滑动窗口（Redis Lua）；激活/心跳/bootstrap 独立阈值。
- 枚举：卡密 130-bit 熵 + 失败计数 + 渐进封禁 + 风险事件。
- 并发：在线名额 Redis Lua 原子裁决；设备名额 DB 事务原子裁决。
- 审计：追加写审计日志，覆盖登录/制卡/导出/吊销/解绑/封禁/管理员变更。

## 合规与隐私

- 机器码数据为摘要形态，设计上不可逆推原始硬件序列号。
- 数据保留：审计日志建议 ≥ 1 年（按当地法规）；风险事件 ≥ 90 天；在线心跳不入库历史。
- 用户数据导出/删除流程按需在管理面扩展（预留 `licenses.note` 与事件导出）。

## 发布检查清单

- [ ] 密钥全部来自 KMS/Secret 注入（`grep -r` 无硬编码密钥）
- [ ] `VFT_ENV=prod` 下 cookie Secure、TLS 校验全开
- [ ] gosec/govulncheck/trivy 无 HIGH/CRITICAL
- [ ] E2E：抓包无明文卡密；篡改租约被拒；重放被拒；吊销一个心跳内生效
- [ ] 备份恢复演练通过（RPO ≤ 5min，RTO ≤ 1h）
- [ ] 管理员 MFA 已启用、初始口令已轮换
