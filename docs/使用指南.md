# Vertify 卡密验证系统使用与脚本接入指南

本文面向两类使用者：

- **系统管理员/总经销商**：部署服务、进入后台、创建产品、套餐、卡密和代理商。
- **软件开发者**：把卡密验证植入自己的 Windows C++ 程序或游戏辅助客户端。

> 重要说明：客户端运行在用户自己的电脑上，不存在绝对防破解方案。Vertify 的安全目标是机器绑定、短租约心跳、快速吊销、服务端策略控制和提高绕过成本。

本文示例中的 `127.0.0.1`、`localhost`、开发数据库连接串和测试密码只适用于本机开发或 CI，不能复用于生产。生产环境必须使用托管 PostgreSQL/Redis、TLS、可信代理和外部密钥管理，不要直接暴露管理 API、指标、Redis 或 PostgreSQL。


| 组件 | 作用 | 默认地址 |
|---|---|---|
| 客户端 API | 激活、心跳、续费、解绑 | `http://127.0.0.1:8080`（开发） |
| 管理 API | 登录、产品、套餐、卡密、许可证、风控 | `http://127.0.0.1:8081`（开发） |
| 管理前端 | 浏览器后台 | `http://127.0.0.1:5173`（开发） |
| PostgreSQL | 业务数据、审计、许可证状态 | `54329`（本地开发映射） |
| Redis | 限流、在线名额、防重放缓存 | `6399`（本地开发映射） |
| Worker | 清理会话、补记过期事件 | 后台服务，无网页端口 |

生产环境不要直接把管理端口和 Redis/PostgreSQL 暴露到公网。客户端 API、管理后台和指标端口应通过网关、内网和 TLS 访问控制隔离。

## 二、首次启动开发环境

### 2.1 准备依赖

开发机需要：

- Docker Desktop，或 Go 1.27+、PostgreSQL 16、Redis 7；
- Node.js 20+；
- Windows C++ 客户端编译需要 CMake 和 MSVC/MinGW。

进入项目目录：

```powershell
cd <repo-root>
```

### 2.2 生成开发密钥

不要手写密钥，也不要把生产密钥提交到 Git。使用项目密钥生成器：

```powershell
cd apps\license-api
go run .\cmd\keygen > dev.env
```

生成的 `dev.env` 只用于本地开发。生产环境应由 KMS、Vault 或 Kubernetes Secret 注入。

### 2.3 使用 Docker Compose 启动

在项目根目录执行：

```powershell
docker compose -f deploy\compose\docker-compose.yml up --build
```

Compose 会启动：

- PostgreSQL；
- Redis；
- Go API；
- Worker；
- 管理后台静态站点。

如果使用本地 Vite 开发前端，另开一个终端：

```powershell
cd apps\admin-web
npm ci
npm run dev
```

浏览器打开：

```text
http://127.0.0.1:5173
```

### 2.4 本地直跑 API

不使用 Docker 时，先准备 PostgreSQL 和 Redis，然后设置环境变量。PowerShell 示例：

```powershell
$env:VFT_ENV = "dev"
$env:VFT_DATABASE_URL = "postgres://vertify:vertify@127.0.0.1:54329/vertify?sslmode=disable"
$env:VFT_REDIS_URL = "redis://127.0.0.1:6399/0"
$env:VFT_INITIAL_ADMIN_USER = "admin"
$env:VFT_INITIAL_ADMIN_PASSWORD = "请设置至少12位开发密码"
$env:VFT_SIGN_KEYS = "从 keygen 输出复制"
$env:VFT_SIGN_ACTIVE_KID = "sign-a"
$env:VFT_KEX_KEYS = "从 keygen 输出复制"
$env:VFT_CARD_HMAC_KEY = "从 keygen 输出复制"

cd apps\license-api
go run .\cmd\migrate up
go run .\cmd\server
```

默认端口：

```text
客户端 API：http://127.0.0.1:8080
管理 API：http://127.0.0.1:8081
指标：http://127.0.0.1:9090
```

### 2.5 本地 HTTPS 联调

客户端 SDK 只应在生产使用 HTTPS。开发联调可以生成自签名证书：

```powershell
cd apps\license-api
go run .\cmd\tlscert ..\..\.tools\tls
$env:VFT_TLS_CERT = "..\..\.tools\tls\cert.pem"
$env:VFT_TLS_KEY = "..\..\.tools\tls\key.pem"
go run .\cmd\server
```

自签名证书只用于本机测试。生产必须使用受信任证书，或由可信 TLS 网关终止 TLS，并明确设置 `VFT_TRUSTED_TLS_PROXY=true`。

## 三、第一次登录管理后台

1. 打开 `http://127.0.0.1:5173`。
2. 使用 `VFT_INITIAL_ADMIN_USER` 和 `VFT_INITIAL_ADMIN_PASSWORD` 登录。
3. 首次登录会强制修改初始密码。
4. 修改后重新登录，并建议立即启用 TOTP 多因素认证。
5. 不要把管理员密码写入脚本、截图、群聊或版本库。

管理后台主要模块：

- **仪表盘**：查看卡密状态、许可证、在线数、风险事件和代理数量。
- **产品与套餐**：创建软件产品及天卡、周卡、月卡、永久卡、次卡等套餐。
- **卡密批次**：批量生成卡密，只在生成时显示完整卡号。
- **卡密管理**：冻结、解冻、吊销、作废、备注和查看来源代理商。
- **许可证**：查看激活后的许可证、设备、到期时间和策略版本。
- **代理商**：管理渠道、余额和资金流水。
- **用户管理**：管理账号制用户、机器绑定和续期。
- **风控与封禁**：按 IP、设备、公钥、卡密前缀、版本号等维度处置风险。
- **软件发布**：发布公告和版本最低要求。
- **接口限流**：配置不同接口的访问频率。
- **密钥状态**：查看公钥和密钥轮换状态。

## 四、创建产品、套餐和卡密

### 4.1 创建产品

产品代表你的一个软件或业务项目，例如：

```text
产品名称：我的游戏辅助
产品代码：自动生成或填写 AUXPRO
```

产品代码会出现在客户端 SDK 的 `product_code` 配置中。一个客户端产品应固定使用一个产品代码，不要在运行时从用户输入读取产品代码。

### 4.2 创建套餐

套餐决定许可证策略。常见配置如下：

| 用途 | 类型 | 示例配置 |
|---|---|---|
| 天卡 | 时长卡 | `duration_days=1` |
| 周卡 | 时长卡 | `duration_days=7` |
| 月卡 | 时长卡 | `duration_days=30` |
| 年卡 | 时长卡 | `duration_days=365` |
| 永久卡 | 永久卡 | 无到期时间 |
| 次卡 | 次数卡 | `uses_total=次数` |
| 固定期卡 | 固定期卡 | 从制卡时间开始计算 |

建议初始配置：

```text
设备绑定上限：1
并发在线上限：1
心跳间隔：60 秒
租约 TTL：300 秒
离线宽限：按你的业务决定，重要功能建议较短
```

#### 设备绑定上限和并发上限的区别

- **设备绑定上限**：一张许可证最多绑定几台设备。比如 1 表示只能绑定一台机器。
- **并发在线上限**：同一时间最多允许几台设备在线。比如绑定了 3 台但并发为 1，则同一时间只能有 1 台续租成功。

修改套餐状态会影响后续心跳策略。退役套餐通常用于停止新激活；如果需要立即停止已有客户端，应同时冻结或吊销相关许可证。

### 4.3 创建天卡、周卡、月卡

有两种方式：

#### 方式 A：提前创建套餐

分别创建：

```text
天卡：1 天
周卡：7 天
月卡：30 天
```

制卡时选择对应套餐。

#### 方式 B：制卡时自定义天数

进入“卡密批次 → 制卡”，选择：

```text
产品 → 自定义时长 → 填写天数
```

系统会自动创建或复用该产品对应天数的自定义套餐，例如 15 天、45 天、90 天，不需要手动填写套餐代码。

### 4.4 批量制卡

1. 进入“卡密批次”。
2. 点击“制卡”。
3. 选择产品、套餐和卡类型。
4. 填写数量和备注。
5. 确认生成。
6. 立即下载 CSV 或复制保存完整卡号。

完整卡号只在生成结果窗口中显示一次。数据库只保存卡密检索用的 HMAC 值，不保存可直接还原的明文卡密。

> 如果关闭明文窗口又丢失卡号，系统无法从数据库恢复完整卡号。请在生成后立即导出，并用安全方式保存。

### 4.5 授权卡和续费卡

- **授权卡**：用于首次激活，创建新的许可证并绑定设备。
- **续费卡**：只能在已经激活的许可证上使用，将套餐时长叠加到现有到期时间。

续费卡不会新建一台设备，也不会把永久许可证转换成时长许可证。

## 五、Windows C++ 程序接入

当前正式推荐的客户端 SDK 是 `sdk/windows-cpp`。它提供 C ABI 和 C++ RAII 封装，适合：

- C++ 游戏辅助；
- C/C++ DLL；
- 使用 C ABI 的其他 Windows 宿主程序。

### 5.1 构建 SDK

在项目根目录执行：

```powershell
cd sdk\windows-cpp
cmake -S . -B build
cmake --build build --config Release
```

构建产物包括：

```text
build/vertify_sdk 静态库
build/activate_demo.exe 示例程序
build/selftest.exe 密码学自测程序
```

先运行自测：

```powershell
build\selftest.exe
```

看到 `selftest: PASS` 后再接入自己的程序。

### 5.2 最小 C++ 接入代码

```cpp
#include <vertify/license_sdk.h>
#include <cstdio>
#include <string>

static void on_state(vft_state_t state, void*) {
    switch (state) {
    case VFT_STATE_ACTIVE:
        std::printf("授权有效\\n");
        break;
    case VFT_STATE_STALE:
        std::printf("网络中断，租约已超过离线宽限\\n");
        break;
    case VFT_STATE_REVOKED:
        std::printf("许可证已被冻结或吊销\\n");
        break;
    default:
        std::printf("授权状态异常\\n");
        break;
    }
}

int main() {
    vft_config cfg{};
    cfg.server_url = "https://api.example.com";
    cfg.product_code = "AUXPRO";
    cfg.client_version = "1.0.0";
    cfg.insecure_skip_tls_verify = 0; // 生产必须为 0

    vertify::License license;
    vft_err_t err = license.init(cfg);
    if (err != VFT_OK) {
        std::printf("初始化失败：%s\\n", vertify_err_str(err));
        return 1;
    }

    // 从你的登录窗口、配置文件或命令行获得卡密。
    std::string card = get_card_from_your_ui();

    if (license.state() == VFT_STATE_NOT_ACTIVATED) {
        err = license.activate(card);
        if (err != VFT_OK) {
            std::printf("激活失败：%s\\n", vertify_err_str(err));
            return 1;
        }
    }

    err = license.start_heartbeat(on_state, nullptr);
    if (err != VFT_OK) {
        std::printf("启动心跳失败：%s\\n", vertify_err_str(err));
        return 1;
    }

    // 每次执行受保护功能前都调用 SDK 判断，不要自己缓存 authorized 布尔值。
    if (license.has_feature("aimbot")) {
        run_aimbot();
    }
    if (license.has_feature("esp")) {
        run_esp();
    }

    // 程序退出前先停心跳，再销毁 License 对象。
    license.stop_heartbeat();
    return 0;
}
```

上面 `get_card_from_your_ui()`、`run_aimbot()` 和 `run_esp()` 是你的业务代码，需要替换成实际实现。

### 5.3 把 SDK 植入现有 C++ 游戏辅助

推荐在你的程序中增加一个独立授权模块，不要把验证逻辑散落在各个功能函数中：

```text
YourApp
 ├─ LicenseManager
 │   ├─ 初始化 SDK
 │   ├─ 卡密输入/激活
 │   ├─ 心跳生命周期
 │   ├─ 状态回调
 │   └─ 功能门禁
 ├─ LoginWindow
 ├─ FeatureA
 └─ FeatureB
```

建议流程：

1. 程序启动。
2. 初始化 `vft_config`。
3. 检查 `license.state()`。
4. 未激活时显示卡密输入框。
5. 调用 `license.activate(card)`。
6. 激活成功后调用 `license.start_heartbeat(...)`。
7. 每次启用功能前调用 `license.has_feature("功能名")`。
8. 收到 `VFT_STATE_REVOKED` 时关闭受保护功能。
9. 收到 `VFT_STATE_STALE` 时根据业务决定暂停功能或进入有限离线模式。
10. 退出时调用 `stop_heartbeat()`。

不要把以下逻辑放在客户端自行实现：

- 自己解析数据库；
- 自己判断卡密是否过期；
- 自己修改租约时间；
- 只判断一个永不更新的 `bool authorized`；
- 把私钥、设备状态或完整卡密写入明文日志。

### 5.4 C ABI 接入其他 Windows 语言

SDK 头文件提供 C ABI 函数，例如：

```cpp
vertify_init
vertify_activate
vertify_start_heartbeat
vertify_get_state
vertify_has_feature
vertify_redeem
vertify_deactivate
vertify_shutdown
```

如果你的脚本语言可以调用 Windows DLL 的 C 函数，可以制作一个 DLL 包装层，再通过 FFI/ctypes 调用。需要注意：当前仓库默认构建的是静态库，不是现成 DLL。制作 DLL 时应：

1. 将 CMake 的 `add_library(vertify_sdk STATIC ...)` 改为 `SHARED`，或另建一个 DLL wrapper 项目。
2. 对外只导出 `extern "C"` 的 C ABI 函数。
3. 不要跨 DLL 边界传递 C++ `std::string`、STL 容器或异常。
4. 确保宿主和 DLL 使用一致的 x64、运行库和编译器 ABI。
5. 把 SDK 的静态库和第三方依赖正确链接到 DLL。
6. 在正式分发前签名 DLL，并提供依赖的运行库。

### 5.5 Python 脚本的现实情况

仓库中的 Python 文件目前是**实验性协议示例**，不能用于生产激活，原因是它还没有完整实现：

- 设备 PoP 签名；
- nonce 和单调序列号；
- 服务端要求的 `/v1/heartbeat` 心跳协议；
- 与 C++ SDK 等价的本地设备密钥保护。

因此不要把当前 `sdk/python/vertify_client.py` 直接当作商业脚本的生产授权模块。Python 脚本若必须接入，推荐两种方式：

- 使用 C++ 编译一个 DLL wrapper，再用 `ctypes`/`cffi` 调用 C ABI；
- 把关键授权逻辑放在受保护的 C++ 模块中，Python 只调用“初始化、激活、查询功能状态”等少量接口。

不要为了让 Python 代码“能跑”而在服务端增加无签名后门，这会破坏设备绑定和防重放安全模型。

## 六、续费、换机和解绑

### 6.1 客户端续费

C++ SDK 中：

```cpp
vft_err_t err = license.redeem(renewal_card);
if (err != VFT_OK) {
    std::printf("续费失败：%s\\n", vertify_err_str(err));
}
```

续费卡必须和当前许可证属于同一产品，并且是续费卡类型。

### 6.2 用户主动换机

客户端准备卸载或换机时：

```cpp
license.stop_heartbeat();
vft_err_t err = license.deactivate();
```

解绑成功后，设备名额会被释放。网络不可用时不要反复重试高风险操作，应由管理员在后台核验后解绑。

### 6.3 管理员解绑

后台进入许可证详情或设备管理，确认设备、许可证和用户后执行解绑。解绑操作会写入事件和审计记录。

### 6.4 冻结、吊销、作废

- **冻结**：通常是临时停止使用，可后续解冻。
- **吊销**：永久处置许可证或卡密，通常不可恢复。
- **作废**：使卡密不能再使用，适合误制卡、测试卡和运营废弃卡。

吊销和作废前应填写原因。生产运营建议先冻结观察，再根据风险决定是否吊销。

## 七、常见错误和处理方式

| 错误 | 含义 | 建议 |
|---|---|---|
| `VFT_E_CARD_INVALID` | 卡密格式错误 | 检查复制内容和输入空格 |
| `VFT_E_CARD_NOT_FOUND` | 卡密不存在 | 检查产品环境、卡密是否复制完整 |
| `VFT_E_CARD_FROZEN` | 卡密被冻结 | 联系运营人员核验 |
| `VFT_E_CARD_REVOKED` | 卡密已吊销 | 不能继续使用 |
| `VFT_E_CARD_DEPLETED` | 次数已用尽 | 更换卡密或购买新次数 |
| `VFT_E_LICENSE_FROZEN` | 许可证被冻结 | 联系管理员 |
| `VFT_E_LICENSE_REVOKED` | 许可证已吊销 | 不能继续使用 |
| `VFT_E_LICENSE_EXPIRED` | 许可证到期 | 使用续费卡 |
| `VFT_E_DEVICE_LIMIT` | 设备绑定已满 | 先解绑旧设备 |
| `VFT_E_CONCURRENT_LIMIT` | 并发名额已满 | 关闭其它在线实例后重试 |
| `VFT_E_NETWORK` | 网络错误 | 检查 API 地址、DNS、TLS 和防火墙 |
| `VFT_E_BAD_RESPONSE` | 服务响应不可信 | 检查证书、公钥固定和服务端版本 |
| `VFT_E_RATE_LIMITED` | 请求过于频繁 | 等待后重试，不要循环爆发请求 |
| `VFT_E_BANNED` | 命中风控策略 | 不要向最终用户暴露详细风控规则 |
| `VFT_E_VERSION_TOO_OLD` | 客户端版本过低 | 发布新版本并更新 `client_version` |

### 客户端一直显示 STALE

按以下顺序检查：

1. 服务端 API 是否运行。
2. 客户端配置是否使用了正确域名和端口。
3. TLS 证书是否受信任。
4. 防火墙是否允许访问客户端 API。
5. 管理后台的套餐心跳间隔和租约 TTL 是否合理。
6. Redis 是否正常运行。
7. 客户端系统时间是否偏差过大。

### 激活成功但功能没有打开

检查：

1. 套餐的“功能列表”是否包含完全一致的字符串，例如 `aimbot`。
2. 代码中调用的功能名是否大小写一致。
3. 是否错误地缓存了旧租约。
4. 心跳是否启动。
5. 当前状态是否为 `VFT_STATE_ACTIVE`。

## 八、上线前检查清单

### 服务端

- [ ] 生产环境使用 TLS 1.3 或可信 TLS 网关。
- [ ] 管理 API 不直接暴露公网。
- [ ] PostgreSQL 和 Redis 不暴露公网。
- [ ] 生产密钥来自 KMS/Vault/Secret，不来自源码或开发文件。
- [ ] 已修改初始管理员密码并启用 MFA。
- [ ] 已部署 Worker。
- [ ] 已配置数据库备份和恢复演练。

## 九、推荐的项目接入方式

如果你正在开发一个 Windows 游戏辅助，推荐目录结构：

```text
YourAssistant/
├─ src/
│  ├─ main.cpp
│  ├─ license_manager.cpp
│  ├─ license_manager.h
│  └─ features/
├─ third_party/
│  └─ vertify/
│     ├─ include/vertify/license_sdk.h
│     └─ lib/vertify_sdk.lib 或 libvertify_sdk.a
└─ config/
```

`LicenseManager` 只负责：

- 保存 SDK 句柄；
- 接收用户输入的卡密；
- 激活和续费；
- 管理心跳线程；
- 对外提供 `is_feature_enabled()`；
- 转换错误码和状态。

业务模块不要直接操作底层租约或设备签名。这样以后更换服务端地址、套餐策略或 SDK 版本时，只需要修改授权模块，不会影响功能代码。
